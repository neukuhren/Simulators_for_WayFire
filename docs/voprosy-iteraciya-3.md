### 19. Чем заменить 10B? (блокер)

«Серое» магазинное IPA в Simulator я **не делаю**. В открытых источниках этот класс задач упирается в расшифровку FairPlay (DRM App Store) и правку чужого бинарника под платформу симулятора. Даже если бинарник как-то запустится, приложение с pinning и HUMAN SDK, скорее всего, не отдаст полезный HTTPS в прокси.

- **A.** Физические iPhone (у вас это уже работает, ответ 17A). Этот репозиторий: каталог профилей, цикл «сейчас очередь аккаунта N», приём curl, который вы сами экспортируете из Charles/Proxyman, сохранение в `secrets/` (не в git).
- **B.** Настаиваю на 10B (Simulator + серое IPA + автоперехват). Понимаю, что кода автоматизации в этом репо не будет.
- **C.** Android-устройства/эмуляторы, съём curl по-прежнему вручную из прокси, как 17A.
- **D.** Вообще без устройств в этом репо: только CLI «вставил curl → сохранил в профиль», цикл очереди — подсказка в терминале.

**Рекомендация: A или D.** У вас 17A уже работает; 16 сужает проект до «получить и сохранить curl». Тогда Simulator не даёт новой ценности, только хрупкость. **A** если хотите, чтобы скрипт ещё вёл очередь «какой аккаунт сейчас». **D** ещё проще и не зависит от Xcode. **B** — зафиксируем отказ и остановимся на документации. **C** имеет смысл только если iPhone станет узким местом, а Android-прокси вам привычнее.

### 20. В каком виде сохранять curl для другого проекта?

- **A.** Сырой текст команды `curl ...` (как копирует Charles / Safari). Один файл на аккаунт, перезапись при обновлении.
- **B.** Разобранный JSON: `url`, `method`, `headers`, `body` — удобнее парсить в `import_curl_secret`.
- **C.** Оба: `request.curl.txt` + `request.json`.
- **D.** Формат как в другом проекте; пришлю пример **без** боевых токенов (маски `Authorization`, cookie, PX).

**Рекомендация: D, иначе C.** Без примера импортёра легко сохранить «не тот» набор заголовков, и второй проект начнёт отбрасывать секреты. Если примера не будет — **C**: человеку удобно глазами проверить `.txt`, коду — `.json`.

### 21. Какие запросы считать «успешным обновлением»?

В UI уйдёт не один GraphQL.

- **A.** Только `queryName=GetAvailableJobs` (его заголовки потом годятся и для claim в другом проекте — так вы описывали).
- **B.** Любой `wayhome/graphql` с `Authorization` и `X-PX-AUTHORIZATION`.
- **C.** Пачка: последний GetAvailableJobs + отдельно заголовки, без тела.
- **D.** Пока не знаем, сохранять все graphql за сессию в подпапку.

**Рекомендация: A.** Вы сами написали, что для claim те же заголовки, что у poll. Один канонический запрос проще для очереди «аккаунт обновлён / не обновлён». **D** быстро раздует диск и секреты.

### 22. Как curl попадает в этот проект?

- **A.** Человек копирует из Charles и вставляет в CLI (`pbpaste` / файл).
- **B.** Кидает `.txt` / HAR в папку `inbox/`, скрипт подхватывает.
- **C.** Charles/Proxyman сам пишет экспорт в папку (если включите это в прокси сами; я не настраиваю MITM Wayfair).
- **D.** Нужен полностью безрукий съём из приложения.

**Рекомендация: A или B.** Это продолжает 17A и не требует лезть в чужой клиент. **D = автоперехват чужого приложения — не реализую.**

### 23. Пауза между аккаунтами в круге 1→2→…→10→1

- **A.** Сразу следующий, как только текущий curl сохранён.
- **B.** Фиксированная пауза N минут после каждого (напишите N).
- **C.** Пауза только если сохранение не удалось; иначе сразу дальше.
- **D.** Круг не чаще чем раз в T минут на аккаунт (напишите T).

**Рекомендация: A для очереди «человек + Charles»:** оператор сам задаёт темп. Жёсткий 24/7-робот по всем десятерым я не ставлю. Если нужен предохранитель от слишком частых обновлений одного и того же — **D** с T, которое вы замерите по 401 в другом проекте.

### 25. Таймзона в этом репозитории

`startDate` в poll считается в зоне аккаунта (у вас в примере America/Los_Angeles). Этот проект curl только сохраняет.

- **A.** Таймзону здесь не храним, она живёт во втором проекте.
- **B.** В профиле поле `timezone` (IANA), только как подпись для оператора, на запросы не влияет.
- **C.** Нужно подставлять дату в сохраняемый curl.

**Рекомендация: B.** Нулевая цена, меньше путаницы «какой iPhone чей». **C** не нужен: тело GetAvailableJobs другой проект и так пересобирает. **A** тоже ок, если во втором проекте уже есть справочник.
