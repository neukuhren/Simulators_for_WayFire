# Исследование и черновик архитектуры

Статус: **итерация 1 планирования**. Окончательный план не составляю, пока не закрыты вопросы из `docs/voprosy-iteraciya-1.md`.

## Что я проверил в открытых источниках

### 1. Что такое Wayfire в публичном интернете

Публичный проект [Wayfire](https://wayfire.org/) (репозиторий [WayfireWM/wayfire](https://github.com/WayfireWM/wayfire)) — это **3D-композитор Wayland для Linux**, аналог Compiz. У него:

- нет приложения в Apple App Store;
- нет пользовательских аккаунтов «войти в Wayfire»;
- нет мобильного HTTP API, который приложение слало бы как curl;
- есть только IPC (сокет композитора) через пакеты вроде [pywayfire](https://github.com/WayfireWM/pywayfire) — это управление окнами Linux-рабочего стола, не мобильное приложение.

Похожие имена в App Store (Wayfair, Wayfare) — другие продукты и к описанной задаче не подходят.

**Вывод:** либо «Wayfire» — ваше закрытое/внутреннее приложение, либо название нужно уточнить ссылкой на App Store. Без этого нельзя спроектировать установку, вход и «обновление данных».

### 2. iPhone Simulator на Mac ≠ эмулятор с App Store

Официальный инструмент Apple на Mac — **Simulator** (Xcode), не полноценный эмулятор железа.

По документации и практике Apple / Stack Overflow / Apple Developer Forums:

- в Simulator **нельзя установить приложения из App Store**;
- бинарник из App Store (`.ipa` под ARM-устройство) **не запускается** в Simulator;
- Simulator принимает только сборку, собранную **под симулятор** (`.app` из Xcode);
- вход в Apple ID / App Store в Simulator для скачивания приложений **не поддерживается**.

Следствие: сценарий «10 симуляторов → уникальный Apple ID → скачать Wayfire из App Store» **на штатном Simulator нереализуем**.

Реальные устройства (физические iPhone) App Store поддерживают. Облачные фермы устройств (BrowserStack, Sauce Labs, AWS Device Farm и т.п.) обычно тоже требуют **ваш** `.ipa`/`.app`, а не произвольное приложение из магазина под чужим аккаунтом.

Коммерческие ARM-эмуляторы уровня Corellium — дорогие enterprise-продукты для исследования **своих** сборок и безопасности, не замена «10 Apple ID + App Store».

### 3. Автоматизация «по очереди запустить симулятор и приложение»

Если речь про **ваше** приложение, собранное под Simulator, оркестрация на одном Mac выглядит так:

1. Каталог симуляторов: `xcrun simctl list`.
2. По очереди: `boot` → дождаться готовности → `launch` по bundle id → сценарий жестов/экранов → `shutdown`.
3. UI-сценарий: XCUITest (если есть исходники) или Appium + XCUITest-драйвер.

Это хорошо стыкуется с требованием «по одному», экономит RAM и снижает гонки.

### 4. «Перехватить curl из приложения»

Сохранять исходящий HTTP как curl — обычный приём **отладки своего** клиента. Чистые варианты, если приложение ваше:

- логировать запрос в debug-сборке (самый устойчивый путь: нет certificate pinning, нет сюрпризов iOS);
- использовать свой backend / официальный API и вообще не гонять UI.

Перехват трафика чужого приложения (MITM-прокси, обход pinning, извлечение токенов из 10 аккаунтов) — это уже вмешательство в чужой клиент и чужие сессии. Такой путь в этом проекте **не планирую и не буду реализовывать**.

## Предварительные развилки (не финальный план)

Зависят от ответов на вопросы.

| Если… | Тогда разумная архитектура |
| --- | --- |
| Есть официальный HTTP API Wayfire | Python в `venv` на Mac (или любом ПК): вход по аккаунтам, обновление данных, сохранение запросов как шаблонов **без** симуляторов. Симуляторы не нужны. |
| Это ваше iOS-приложение, исходники есть | Один Mac + Xcode Simulator + сборка `.app` + XCUITest/Appium. «Curl» лучше получать из логов debug-сборки, не из сети. |
| Нужна проверка на разных моделях экрана | Имеет смысл 3–5 симуляторов разных форм-факторов, не 10 Apple ID. Модель устройства ≠ отдельный аккаунт. |
| Это чужое приложение из App Store, цели — чужие сессии и скрытый API | Этот вариант я не проектирую. Нужен официальный API или договорённость с правообладателем. |

## Что точно будет в репозитории после планирования (ожидание)

- Python-проект с обязательным `venv`.
- Каталог профилей симуляторов (имена, UDID, модель) **без паролей**.
- Скрипты оркестрации только под выбранную легитимную схему.
- Локальная папка для чувствительных артефактов в `.gitignore`.

## Ограничение среды Cursor Cloud

Этот агент работает в Linux-облаке. Xcode, Simulator и App Store здесь недоступны. Реализация и прогон — на вашем Mac; в git попадает код и документация, не содержимое симуляторов.
